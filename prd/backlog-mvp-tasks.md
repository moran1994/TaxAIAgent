## M0 准备（约 1 周）

### M0-01 锁定增值税语料范围与 50 题清单
**Why：** 没有边界就会做成全税种百科，冷启动成本失控（B3）。  
**What：** 列出首发语料清单（法规/公告**官方来源 URL 或文件**）+ 50 道黄金问答；题干可用蒸馏草稿，但「应引文号/条款」必须人工确认。  
**Acceptance：**
- [ ] 语料清单 ≤ 约定篇数，均属增值税/常见发票口径，每条有权威来源
- [ ] 50 题每题有「标准问 + 应引文号/条款」（条款可链到后续 chunk）
- [ ] 产品签字确认 Out of Scope 税种列表
- [ ] 注明：不从竞品库未授权抓取全文
**估点：** M · **角色：** T+P · **依赖：** 无

### M0-02 免责声明与拒答边界模板
**Why：** 上线前必须划清「参考意见 vs 鉴证」，降低法务风险（E1）。  
**What：** 答案页固定免责文案；高风险主题拒答/强制转专家规则表。  
**Acceptance：**
- [ ] 法务或负责人确认模板可上线
- [ ] 拒答主题表 ≥10 条可配置
- [ ] 文案可被前端/Prompt 引用（单一来源）
**估点：** S · **角色：** P（+法务） · **依赖：** 无

### M0-03 专家供给冷启动
**Why：** 无专家则按单闭环空转（G3）。  
**What：** 招募 ≥5 名持证意向；约定分成比草案、SLA 24h、试接须知。  
**Acceptance：**
- [ ] ≥5 人书面/表单确认愿试接
- [ ] 分成比例与结算周期写明（可改）
- [ ] 至少 3 人完成试接说明阅读
**估点：** M · **角色：** Ops+P · **依赖：** 无（可与 M0-01 并行）

### M0-04 技术脚手架与环境
**Why：** 后续问答/工单需要统一仓库与环境。  
**What：** 前后端仓库或 monorepo、dev/staging、环境变量、基础 CI。  
**Acceptance：**
- [ ] staging 可部署空壳页
- [ ] LLM API Key / DB 仅走密钥管理
- [ ] README 含本地启动步骤
**估点：** M · **角色：** BE+FE · **依赖：** 无

## M1 知识 + 强制引用问答（约 2–3 周）

### M1-01 条款知识对象 Schema
**Why：** 图谱与引用需要稳定对象，避免纯文件堆叠无法过滤时效。  
**What：** Policy / Clause / Condition（简）字段；生效/废止；税种标签；上下架。  
**Acceptance：**
- [ ] Schema 文档 + 迁移/建表完成
- [ ] 支持按税种、效力状态查询
- [ ] 预留 `org_id` 可空（挂载扩展）
**估点：** M · **角色：** BE · **依赖：** M0-01（字段对齐）

### M1-02 原文导入 + 蒸馏辅助切块/打标
**Why：** 检索与强制引用的前提是切块质量（PRD F2）；用知识库蒸馏加速结构化采集，但必须守住「原文真源」，否则 F1 门禁与产品信任破产。  
**What：**  
建立「权威原文 →（规则+LLM 蒸馏）→ 结构化切块/标签 → 专家质检 → 可引用入库」流水线。

**流水线步骤**
1. **原文落地**：官方文件/页面落对象存储；记录来源 URL、文号、发布日、效力状态  
2. **解析**：PDF/HTML → 纯文本；尽量保留条/款标题结构  
3. **切块（规则优先）**：按「第×条 / 第×款」切；规则切不动再 LLM 辅助切，**切块正文必须是原文子串**（允许空白归一，禁止改写）  
4. **蒸馏打标（LLM）**：税种、主题标签、适用条件草稿、现行/废止提示、同义检索词  
5. **蒸馏题库草稿（可选）**：由条款生成「用户可能怎么问」→ 供 M0-01/M1-08 人工改定  
6. **质检门禁**：未过检不得进检索索引（仅可进 `draft`）  
7. **入库**：通过后 `published` + 建向量/关键词索引  

**质检比例（MVP 最低）**

| 对象 | 抽检/全检 | 通过标准 |
|------|-----------|----------|
| 切块原文忠实度 | **首批 100%**；稳定后可改为 30% 抽检 | chunk 文本可在原文定位；条款号正确 ≥98% |
| 蒸馏标签/适用条件 | **≥30% 抽检**（高风险主题 100%） | 标签不误导；条件句不与原文矛盾 |
| 蒸馏出的问答草稿 | **100% 人工改定**后才进黄金集 | 应引条款与原文一致；禁止无依据题 |

**禁止项（写进 Definition of Done）**
- ❌ 无权威原文、仅靠模型「回忆」生成的法条入库  
- ❌ 改写/摘要后的文字当作可引用原文（摘要可另存 `note`，不可作 citation）  
- ❌ 未标注来源 URL/文号的切块发布  
- ❌ 未过质检的 `draft` 进入线上检索  
- ❌ 未授权刮取竞品知识库全文做蒸馏源  

**Acceptance：**
- [ ] M0 语料全部有原文件/来源记录，切块可回溯
- [ ] 发布态切块：**正文为原文子串** + 文号 + 条款号
- [ ] 蒸馏仅写入标签/条件/草稿字段；citation 只指向原文 chunk
- [ ] 首批切块 100% 忠实度质检通过；标签 ≥30% 抽检通过并留质检表
- [ ] `draft` / `published` 状态可分；运营可驳回重蒸
- [ ] 人天耗时有记录（对照 B3：目标 ≤15 人天量级完成窄库）
- [ ] 禁止项有检查清单，发版前勾选
**估点：** L–XL · **角色：** AI+T+BE · **依赖：** M1-01, M0-01

### M1-02b 蒸馏 Prompt 与质检工作台（简）
**Why：** 蒸馏可复跑、质检可留痕，否则每次靠聊天窗口无法回归。  
**What：** 固定「切块校验 / 打标 / 出题」三类 Prompt 版本；表格或简页：抽检、通过/驳回、备注。  
**Acceptance：**
- [ ] Prompt 版本号可查、可回滚
- [ ] 每条发布切块有质检人/时间/结果（可 CSV）
- [ ] 驳回原因枚举：条款号错 / 正文非原文 / 标签误导 / 效力错
**估点：** M · **角色：** AI+FE（表即可） · **依赖：** M1-02（可并行后半）

### M1-03 向量 + 关键词混合检索
**Why：** 文号/专名靠关键词，语义靠向量，税务场景两者都要。  
**What：** Embedding 入库；BM25/关键词；融合 TopK；按现行有效默认过滤。  
**Acceptance：**
- [ ] API：`query → chunks[]`（含 id、文号、原文、分数）
- [ ] 废止条款默认不进结果（可测）
- [ ] 延迟 P95 有基线记录
**估点：** L · **角色：** AI+BE · **依赖：** M1-02

### M1-04 知识运营后台（简）
**Why：** Concierge 期要能上下架、修切块，不能只靠改库。  
**What：** 列表/搜索/预览切块/上下架/触发重索引（可手工按钮）。  
**Acceptance：**
- [ ] 非工程师可完成一次上下架
- [ ] 预览显示条款号与原文
- [ ] 操作写审计日志（谁、何时）
**估点：** M · **角色：** FE+BE · **依赖：** M1-01

### M1-05 LLM Gateway 与 Prompt 版本
**Why：** 控成本、可回滚、统一拒答与免责注入。  
**What：** 模型调用封装、流式、超时重试、Prompt 版本号、token 日志。  
**Acceptance：**
- [ ] 切换 Prompt 版本无需改代码发版（配置或后台）
- [ ] 请求日志脱敏可查
- [ ] 注入 M0-02 免责与拒答规则
**估点：** M · **角色：** BE+AI · **依赖：** M0-02, M0-04

### M1-06 强制引用问答编排
**Why：** 产品差异化核心：无依据不瞎答（PRD F1 / 假设 F1）。  
**What：** 检索 → 无命中则「不确定/拒答」；有命中则生成且绑定 chunk_id；禁止无引用确定性结论。  
**Acceptance：**
- [ ] 自动测：空检索集时不出确定性结论
- [ ] 每条结论结构化字段含 `citation_ids[]`
- [ ] 虚构文号抽测胡答率有统计入口
**估点：** L · **角色：** AI+BE · **依赖：** M1-03, M1-05

### M1-07 用户对话 UI（答案卡片）
**Why：** 用户先看结论再展开依据，才「敢用」（PRD F3）。  
**What：** 登录（手机号可）、多轮对话、流式、答案卡片（结论/依据/边界/免责）、引用侧栏点开原文、「不确定」态与补槽、「转专家」入口占位。  
**Acceptance：**
- [ ] 桌面+移动宽度可用
- [ ] 点击依据可看到原文/文号
- [ ] 「不确定」与「转专家」按钮可曝光打点
**估点：** L · **角色：** FE · **依赖：** M1-06（可先 Mock）

### M1-08 黄金集评测门禁
**Why：** 没有门禁就会带着幻觉放量（PRD F7 / KR1）。  
**What：** 50 题集入库；一键跑批；输出引用正确率、胡答率；&lt;70% 阻断 staging→prod 放量开关。  
**Acceptance：**
- [ ] 本地/CI 可跑评测报告
- [ ] 指标定义书面化（何谓引用正确）
- [ ] 与发布检查清单挂钩
**估点：** M · **角色：** AI+T · **依赖：** M1-06, M0-01

### M1-09 会话与用户基础数据
**Why：** 转专家要打包上下文；后续挂载需要用户/企业主体。  
**What：** 用户、会话、消息表；可选 `enterprise_id` 空字段；导出对话 JSON。  
**Acceptance：**
- [ ] 刷新不丢近史会话（策略约定：保留 N 天）
- [ ] 导出接口含消息与 citation
- [ ] enterprise 字段可空不阻塞
**估点：** M · **角色：** BE · **依赖：** M0-04

## M2 专家按单闭环（约 2 周）

### M2-01 转专家报价与下单
**Why：** 把不确定转化为付费专家单（V2/U2）。  
**What：** 两档标价（如 99/199）；下单页展示将移交的上下文摘要；创建待支付订单。  
**Acceptance：**
- [ ] 从对话一键带入上下文
- [ ] 订单含用户、会话 id、报价、状态
- [ ] 埋点：转专家曝光/点击/下单
**估点：** M · **角色：** FE+BE · **依赖：** M1-07, M1-09

### M2-02 支付（单通道）
**Why：** 真付费才能验 V2；MVP 只接一种支付即可。  
**What：** 微信或支付宝其一；支付成功回调；失败/超时可重新支付；沙箱可测。  
**Acceptance：**
- [ ] 沙箱或真机走通支付成功
- [ ] 支付成功订单→待接单
- [ ] 异常有明确前端提示
**估点：** L · **角色：** BE · **依赖：** M2-01

### M2-03 工单状态机
**Why：** 专家履约与退款、分账都挂在工单上（PRD F4）。  
**What：** 状态：待支付→待接单→处理中→已完成 / 已退款 / 已取消；SLA 24h 截止时间；类型枚举预留 `risk_consult`。  
**Acceptance：**
- [ ] 非法流转被拒绝
- [ ] SLA 超时可标记（可先告警不自动罚）
- [ ] 工单类型字段可扩展
**估点：** M · **角色：** BE · **依赖：** M2-02

### M2-04 专家工作台（简）
**Why：** 专家要能领单、写答复、看倒计时（PRD F5 / G3）。  
**What：** 专家登录；待接池；领单；查看对话+AI 草稿；提交书面答复；可选「建议回流」。  
**Acceptance：**
- [ ] 3 名试接专家无培训文档外帮助下完成一单
- [ ] 用户侧可见专家书面答复
- [ ] 领单互斥（同一单不能两人领）
**估点：** L · **角色：** FE+BE · **依赖：** M2-03, M0-03

### M2-05 分账记账与导出
**Why：** 验平台毛利与专家分成（B1 / PRD F6）；月结可半自动。  
**What：** 每单字段：实付、手续费、专家分成、平台留存；导出 CSV；分成比例配置。  
**Acceptance：**
- [ ] 完成单一笔自动生成分账行
- [ ] CSV 可给财务对账
- [ ] 改分成比例仅影响新单
**估点：** M · **角色：** BE · **依赖：** M2-03

### M2-06 用户评价与退款入口（最小）
**Why：** 质量信号 + 止损；避免差单毁掉供给。  
**What：** 完成后 1–5 星+短评；申请退款工单（MVP 可后台人工处理）。  
**Acceptance：**
- [ ] 评价写入可查
- [ ] 退款申请有状态；人工可打成已退款并冲减分账
**估点：** S · **角色：** FE+BE · **依赖：** M2-04, M2-05

### M2-07 端到端联调与 Concierge 剧本
**Why：** 发布前必须有一条金路径。  
**What：** 脚本：提问→不确定→支付→专家答→评价→分账；修阻塞缺陷。  
**Acceptance：**
- [ ] staging 金路径录像或清单全绿
- [ ] 附录 A 发布门禁逐项打勾
**估点：** M · **角色：** 全员 · **依赖：** M2-01~06, M1-08

## M3 Concierge 放量（约 1–2 周）

### M3-01 指标看板（最小）
**Why：** 盯 KR，决定停损或加码（见 `discovery/metrics-dashboard.md`）。  
**What：** 日报/表：引用正确率（最近评测）、付费单数、SLA、转单点击率、贡献毛利。  
**Acceptance：**
- [ ] 产品每周能不写 SQL 看到 KR
- [ ] 与 PRD KR1–KR5 字段对齐
**估点：** M · **角色：** BE+P · **依赖：** M2-05, M1-08

### M3-02 获客落地页与入口
**Why：** 没有流量验不了愿付。  
**What：** 一页说明价值+分成透明+「开始提问/请专家」；可接微信群/表单获客。  
**Acceptance：**
- [ ] 落地页可访问并链到产品
- [ ] 主要 CTA 可打点
**估点：** S · **角色：** P+FE · **依赖：** M1-07

### M3-03 周复盘与停损机制
**Why：** 避免沉没成本硬冲全量研发。  
**What：** 周会模板；触发停损条件（PRD）；结论写入 `discovery/` 或 `prd/` 决策记录。  
**Acceptance：**
- [ ] 连续 2 周有书面复盘
- [ ] 停损触发时有明确 Next（缩域/改分成/暂停）
**估点：** S · **角色：** P · **依赖：** M3-01
