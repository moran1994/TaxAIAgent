## Epic A — 可信自助问答

### US-A1 提出税务问题并获得答案卡

**Description:** As a 财务/代账用户, I want to 用自然语言提问并看到结构化答案卡, so that 我能快速得到可阅读的结论而不是一篇乱文。

**Design:** TBD · 对话 + 答案卡

**Acceptance Criteria:**
1. 用户提交问题后，界面展示答案卡：结论、依据入口、适用边界、时效说明（字段可空但结构固定）。
2. 请求失败时展示可重试错误态，不展示半截假结论。
3. 同一会话支持追问，追问带上前序上下文。
4. 关键操作（发送、展开依据）支持键盘可达；移动端答案卡可完整滚动阅读。
5. 每次提问产生可追踪的 `ask_submitted` / `answer_shown` 事件。

---

### US-A2 强制引用：无依据不给出确定结论

**Description:** As a 提问用户, I want to 只在有条款依据时看到确定结论, so that 我不会被无来源的幻觉误导。

**Design:** TBD · 引用绑定

**Acceptance Criteria:**
1. 当检索未命中可用条款时，系统不得输出确定性结论句；须展示「依据不足」类状态。
2. 有命中时，每条确定结论至少绑定 1 个 `citation`（条款/chunk id）。
3. 后端日志可查出该次答复的 citation 列表，供抽检。
4. 「无引用硬答」可被监控统计（对齐指标看板）。
5. 单元/集成测试覆盖：无命中 → 不确定态；有命中 → 含 citation。

---

### US-A3 展开查看条款原文与文号

**Description:** As a 提问用户, I want to 点开依据查看文号、生效区间和原文片段, so that 我能自行核对后敢用。

**Design:** TBD · 引用展开

**Acceptance Criteria:**
1. 答案卡上每个引用可展开，至少显示：标题/文号、生效或废止信息、原文片段。
2. 展开失败时有明确提示，不影响结论区其余内容。
3. 用户可复制文号或片段（至少一种复制路径）。
4. 埋点：`citation_attached` 或等价展开事件。
5. 过期/废止条款若被命中，界面有可见标识（MVP 可用文案标「请核实时效」）。

---

### US-A4 适用条件槽位追问

**Description:** As a 提问用户, I want to 在缺关键条件时被追问行业/地区/纳税人类型等, so that 答案不会在错误前提下给出。

**Design:** TBD · 槽位表单/对话追问

**Acceptance Criteria:**
1. 当问题适用依赖未填槽位时，系统先追问，不直接给确定结论。
2. 用户补全后，基于新槽位重新检索并更新答案卡。
3. 用户拒绝补全时，可进入「不确定」态并露出转专家入口。
4. 已填槽位在会话内可编辑。
5. 槽位字段可配置（运营可增改枚举，不必发版改死）。

---

### US-A5 显式不确定并引导下一步

**Description:** As a 提问用户, I want to 在系统没把握时看到清楚说明和下一步, so that 我知道该补信息还是找专家，而不是被糊弄。

**Design:** TBD · 不确定态文案（红队 U2）

**Acceptance Criteria:**
1. 不确定态明确列出：缺什么信息 / 为何不能确定。
2. 同时提供：补槽位、转专家，两个清晰 CTA（文案可 A/B）。
3. 不确定态不得伪装成高置信结论。
4. 埋点：`uncertainty_shown`、后续是否转专家可关联同一会话 id。
5. 法务审定的免责短句在不确定态与确定态均可见。

---

## Epic B — 专家按单与分账

### US-B1 主动或引导转专家

**Description:** As a 提问用户, I want to 在需要时一键申请专家书面答复, so that 复杂问题能得到真人背书。

**Design:** TBD · 转专家 CTA

**Acceptance Criteria:**
1. 入口至少三种可配置触发：用户主动、低置信、高风险标签（MVP 可先做主动+不确定引导）。
2. 点击后进入估价页，带入当前会话摘要（只读预览）。
3. 未登录策略明确：先登录/注册再支付，或允许支付后绑定（二选一，文档写死）。
4. 埋点：`expert_cta_click`。
5. 用户可返回继续 AI 对话，不丢失会话。

---

### US-B2 查看分档报价与分成说明后支付

**Description:** As a 提问用户, I want to 看清档位价格与「咨询费含专家分成」说明后再付款, so that 我知道买的是什么、钱怎么分。

**Design:** TBD · 估价/支付页

**Acceptance Criteria:**
1. 展示至少 2 个可配置价档（如标准/加急），含交付物说明与承诺时限。
2. 页面展示分成说明文案（无需展示精确抽成公式给用户，但须说明「部分费用结算给接单专家」）。
3. 支付成功前工单保持「待支付」；取消/失败不生成有效派单。
4. 支付成功后生成订单号，展示「已支付、等待专家」状态。
5. 埋点：`quote_shown`、`payment_success`；金额与档位入库。

**Concierge-OK:** 可用人工收款 + 表格记账，验收口径不变。

---

### US-B3 支付后自动生成结构化工单

**Description:** As a 专家, I want to 收到带上下文和已检索条款的工单, so that 我不用从零追问就能答复。

**Design:** TBD · 工单详情

**Acceptance Criteria:**
1. 支付成功后系统创建工单，状态为待派/待接。
2. 工单至少包含：用户问题、对话摘要、槽位、AI 草稿（如有）、命中条款列表、用户备注。
3. 专家打开工单可一屏看全上述块；缺块有「无」占位而非空白崩溃。
4. 埋点/日志：`ticket_assigned`（或创建）可关联 payment id。
5. 用户侧可看到工单进度（排队中/处理中/已交付）。

---

### US-B4 专家接单、交付与 SLA

**Description:** As a 专家, I want to 在时限内接单并提交书面答复, so that 我能按约定完成并拿到分成。

**Design:** TBD · 专家工作台

**Acceptance Criteria:**
1. 专家可看待接列表，接单后状态变为进行中，开始 SLA 计时。
2. 专家提交书面答复（富文本或附件+正文至少一种）后，状态变为已交付，用户可见。
3. 超时未接/未交：状态与运营告警可区分（至少列表标红或通知）。
4. 专家可拒单并选择原因；拒单后可重派（MVP 可运营手动重派）。
5. 埋点：`ticket_delivered`；SLA 达成可报表统计。

**Concierge-OK:** 飞书群派单 + 文档交付，状态同步到表格。

---

### US-B5 咨询费按规则分账

**Description:** As a 平台运营, I want to 每笔付费单按规则计算专家分成与平台留存, so that 收入与专家支出挂钩且可对账。

**Design:** TBD · 分账流水（可后台表）

**Acceptance Criteria:**
1. 每笔成功支付生成分账记录：实付、手续费、专家分成、平台留存、分成比、关联工单/专家。
2. 分成比可配置；变更不影响已生成历史单（历史锁比例）。
3. 专家侧可看到「预计到手/已结算」状态（MVP 可仅运营表 + 每周结算通知）。
4. 分账差错可导出对账；与约定比例偏差可稽核（红队/指标要求）。
5. 退款单触发分账冲正或冻结规则（规则文档化，MVP 可先人工）。

**Concierge-OK:** 日结打款表，字段齐全即达标。

---

### US-B6 评价与基础退款入口

**Description:** As a 提问用户, I want to 对专家答复评价并在不满时申请退款, so that 我的风险有限度可控。

**Design:** TBD · 评价/退款（P0 最小；完整流可 P1）

**Acceptance Criteria:**
1. 交付后用户可提交评分（至少 1–5 或有用/无用）与一句评论。
2. 展示退款申请入口与规则摘要；提交后工单进入退款/争议态。
3. 埋点：`rating_submitted`、`refund_requested`。
4. 未评价超过时限可默认关闭评价窗（时限可配置）。
5. 退款处理结果用户可见（通过/驳回+原因）。

## Epic C — 信任、供给与发布门禁

### US-C1 免责声明与专家资质展示

**Description:** As a 提问用户, I want to 看到答复仅供参考及专家资质信息, so that 我清楚责任边界。

**Design:** TBD

**Acceptance Criteria:**
1. 答案卡与专家交付页均展示法务审定免责文案。
2. 专家交付页展示资质摘要（如证书类型/执业年限，字段以合规允许为准）。
3. 未审核资质的专家不得接正式单（状态闸门）。
4. 文案变更走配置，不必改客户端硬编码。

---

### US-C2 专家入驻与分成协议确认

**Description:** As a 专家, I want to 完成资料提交并确认分成结算规则后接单, so that 我知道到手如何计算。

**Design:** TBD · 入驻（Concierge 可表单）

**Acceptance Criteria:**
1. 专家提交必要资料后进入待审/通过/驳回。
2. 通过前须确认分成与结算周期协议（电子勾选+时间戳）。
3. 仅「通过」状态出现在可派单池。
4. 运营可停用专家，停用后不可新接单。

---

### US-C3 黄金集评测门禁

**Description:** As a 运营/研发, I want to 在扩量前跑引用正确率评测, so that 质量不达标时不会对大量用户放开。

**Design:** N/A（工具/脚本）

**Acceptance Criteria:**
1. 存在可重复执行的黄金集（≥50 题目标；Phase 0 允许 ≥10 题小样）。
2. 评测输出引用正确率、无依据硬答率等指标报告。
3. 正确率 &lt;70% 时发布检查失败或需显式豁免记录。
4. 报告可归档到版本/日期，便于对比。

---

### US-C4 关键漏斗埋点对齐指标看板

**Description:** As a 产品经理, I want to 关键行为写入分析事件, so that 我能算可信解决、转化与毛利。

**Design:** N/A · 对照 `discovery/metrics-dashboard.md`

**Acceptance Criteria:**
1. 事件至少覆盖：ask、answer、citation、uncertainty、expert_cta、quote、payment、ticket、rating、refund。
2. 事件带 `user_id`/`session_id`/`ticket_id` 等关联键（无则说明）。
3. Concierge 阶段允许表格等价字段，字段定义与线上事件字典一致。
4. 可用简易查询算出：转专家支付转化、SLA、分账毛利粗算。

## Epic D — Phase 0 Concierge 专项（可与上并行）

### US-D1 Landing 假门验证付费意愿

**Description:** As a 访客, I want to 在落地页了解产品并点击估价/留意向金, so that 团队能验证我是否真有付费意向（V2）。

**Acceptance Criteria:**
1. 落地页含价值主张、答案示例、转专家与分成说明。
2. 可点击估价；可收集意向金或预约。
3. 统计 UV、点击、意向金数量达可汇报粒度。
4. 不承诺未上线能力；不诱导虚假注册。

---

### US-D2 人工 Concierge 跑通首单闭环

**Description:** As a 运营, I want to 用半人工方式完成提问→（可选 AI 草稿）→支付→专家交付→分账记账, so that 在产品化前验证单位经济。

**Acceptance Criteria:**
1. 文档化 SOP：谁收款、谁派单、谁打款、时限多少。
2. 每单字段满足 US-B5 分账记录要求。
3. 累计真单可导出，用于 KR4 毛利评估。
4. 用户与专家均知悉当前为试点服务水平。
